# 마음무대 — 두 개의 틀: 내면의 이야기 만들기 → 선택 바꾸기

> **목표** — 나만의 내면 이야기를 무대로 끄집어내고, 거기서 내가 **자동으로 하던 선택**을 찾아,
> 다른 선택을 하면 어떻게 되는지 직접 보면서 그 자동 선택에서 **벗어난다**.
>
> 그래서 세션은 딱 두 부분이다.
>
> | 부 | 이름 | 하는 일 | 끝나는 조건 |
> | --- | --- | --- | --- |
> | **1부** | 내면의 이야기(무대) 만들기 | 사연 접수 → 아바타 → 한 장면 → 그 장면 속 **자동 선택 지점** 찾기 | "수민이가 여기서 늘 이렇게 한다"가 한 문장으로 나온다 |
> | **2부** | 나의 선택 바꾸기 | 같은 장면, 다른 선택 → 결과 보기 → 비교 → 미래 → 벗어남 | 유저가 "안에서 뭐가 달라졌는지"를 자기 말로 말한다 |
>
> 접수는 "무엇이든 물어보살"처럼 — 앉자마자 "무슨 일로 왔어?"
>
> 기존 문서와의 관계

## 1. 두 틀의 설계 원리

### 1.1 1부 — 내면의 이야기(무대) 만들기

"이야기"는 사건 요약이 아니다. **한 장면 + 그 안에서 반복되는 나의 자동 반응**이다.

```
사연 (접수)       "고백을 해야 할지 모르겠어"
   ↓
한 장면 (open)    침대, 11시, 폰 두 줄
   ↓
몸의 신호 (deepen) 둘째 줄에서 손이 멈춤
   ↓
속의 말 (deepen)  "또야" / "넌 원래 두 번째야"
   ↓
자동 선택 (choice) "ㅋㅋ 원래 그래" 치고 걔 얘기 받아줌  ← 1부가 찾아야 하는 것
   ↓
상대의 속 (meet)  태윤이한텐 수민이뿐
   ↓
거울 (mirror)     "두 번째 줄" — 3인칭으로 한 번 보고, 선택 지점을 유저가 확인
```

1부의 성공 기준 하나: **선택 지점 문장**이 유저 말로 나온다.
> "수민이는 둘째 줄이 오면 손이 멈췄다가, 늘 '원래 그래' 치고 넘어간다."

이게 없으면 2부로 못 넘어간다 — 바꿀 선택이 없으니까. (디렉터는 거울 막에서 반드시 이걸 확인한다.)

### 1.2 2부 — 나의 선택 바꾸기

같은 장면을 **여러 번** 돌린다. 핵심은 "좋은 선택 찾기"가 아니라 **선택이 바뀌면 안에서 뭐가 달라지는지 몸으로 아는 것**.

```
선택 지점 재입장      같은 침대, 같은 두 줄, 손 멈춘 자리에서 정지
   ↓
출구 4개 (replay)   말로 받기 / 자리 뜨기 / 비틀기 / 버티기   ← 주제별로 각색 (§4.5)
   ↓
테이크 2            유저가 고름 → 아바타 실행 → 상대의 현실 반응 → "안에서 뭐가 달라졌어?"
   ↓
테이크 3            다른 출구 → 같은 질문
   ↓
비교                달라진 것만. 채점 없음. "어느 쪽이 편해? 어느 쪽이 진짜 같아?"
   ↓
미래 투사           일주일 뒤 / 1년 뒤 같은 자리. "뭐가 달라?"
   ↓
벗어남 (curtain)    자동 선택 문장 옆에 유저가 새로 쓴 문장을 나란히 둔다
```

2부의 성공 기준: 유저가 **"상황은 안 바뀌었는데 안에서 ___가 달라졌다"**를 자기 말로 한다.
"벗어남"은 상대가 바뀌는 게 아니다. 같은 두 줄이 와도 손이 안 멈추는 것이다.

### 1.3 톤 (기존 그대로)

반말·쉬운 말·짧게. 감정 이름은 유저가 붙인다. 과거형 질문 없음. 처방·채점·사과 서비스 없음. "극단적/던진다" 프레임 금지. 웃음은 디렉터 자기 얘기에서만.

## 2. 접수 — 무슨 일로 왔어? (1부의 문)

### 2.1 물어보살에서 가져오는 것 / 안 가져오는 것

| 가져온다 | 안 가져온다 |
| --- | --- |
| 앉자마자 "무슨 일로 왔어?" | 점·운세·예언 |
| "아~ 그거구나" 한 마디 후 바로 핵심 | 호통·훈계·"다 그래" |
| 사연 두 개면 "뭐가 제일 급해?" | 한 번에 다 풀기 |
| 멋쩍은 손님 농담으로 풀기 (디렉터 자기 얘기로) | 손님 아픔으로 웃기기 |

## 4. 알고리즘

### 4.1 두 부의 흐름

```
┌─ 1부 내면의 이야기 만들기 ──────────────────────────────────┐
│ intake(≤2) → casting(≤3) → draw(1) → open → deepen → meet → mirror │
│                                   └── choice.locate / choice.repeat 가 돌며 선택 지점 후보를 쌓는다 │
│ mirror 끝: choice.confirm — 유저가 한 문장으로 확정해야 2부 진입        │
└─────────────────────────────────────────────────────────────┘
                                   ↓ choicePoint
┌─ 2부 선택 바꾸기 ─────────────────────────────────────────┐

│   → compare → cost → future(1주/1년) → exit(두 문장) → curtain      │

### 4.5 출구 4개 생성 — 주제 × 선택 지점

기본 틀은 개입패턴 6.2 (말로 받기 / 자리 뜨기 / 비틀기 / 버티기). 여기에 **삼킨 말**과 **원래 선택**을 끼운다.

```
① 말로 받기   = choicePoint.swallowed 를 그대로 (없으면 주제 기본 문장)
② 자리 뜨기   = 주제별 "그 자리 벗어나기" (톡→폰 엎기 / 식탁→방으로 / 급식실→다른 테이블)
③ 비틀기      = 화제 돌리기 · 농담 · 내 얘기 먼저
④ 알고 하기   = choicePoint.auto 를 그대로 — "근데 이번엔 알고"   ← 항상 포함. 원래 선택도 선택이다
```

| 주제 | ② 자리 뜨기 | ③ 비틀기 |
| --- | --- | --- |
| love | 답 안 보내고 폰 엎기 | 내 얘기 먼저 꺼내기 |
| puberty | "잠깐 방에 갔다 올게" | "엄마 그 말 세 번째야 ㅋㅋ" |
| friend | 그 테이블 안 가기 | 다른 애한테 먼저 말 걸기 |
| study | 성적표 덮고 나가기 | "이번엔 망했고 다음엔 뭐 할지 얘기해" |
| 안전 플래그 시 | **"도움 요청"으로 교체, 반드시 포함** | — |

### 4.6 테이크 루프

```
for take in 2..N (N≤4, 유저가 멈추면 종료):
   exit = 유저 선택 (칩 or 자유 입력)
   result:
      관찰 1문장 — 아바타가 한 행동 (떨림·망설임 포함)
      보조자아  — 상대의 현실 반응 (사과 서비스 금지; 당황·무심·발끈·바로 읽음 모두 가능)
      질문 1   — "상황은 안 바뀌었는데 {A} 안에서는 뭐가 달라졌어?"
   (선택) continue — 상대 반응 뒤 아바타의 다음 한 수까지 (24턴)
   record take = { exit, bodyAfter, userWords }
   if take == 2 and 유저가 "실패" 신호 → replay.fail ("무대에서 실패는 데이터야") → 같은 출구 다른 타이밍
compare   (minTakes 2)
cost      — "아직"이라고 한 출구에 "뭐가 걸려?" 1회
future    — 1주 뒤 → (깊이 L5 도달 시) 1년 뒤
exit      — 두 문장 나란히
```

테이크 종료 질문은 항상 **"안에서"**다. 겉(상대가 어떻게 됐나)으로 묻지 않는다.

+3  p.id ∈ topics[topic].firstPatterns
+4  movement==="mirror" && p.id==="choice.confirm" && !choicePoint.confirmed   // 1부 종료 강제
+4  movement==="replay" && p.id==="choice.exit" && futureDone && !exitDone      // 2부 종료 강제
-∞  safety.noRoleReversal && p.id==="meet.reversal"
```

### 4.8 프롬프트 브리핑 추가 블록 (`prompts.ts`)

```
[오늘 손님] {primary} — "{intakeText}" / 같이 온 얘기 🧵 {secondary}
[1부 목표] 이 장면에서 {A}가 늘 하는 선택을 유저 말로 한 문장 받기. 아직: {choicePoint.auto ?? "없음"}
[2부 목표] 같은 자리, 다른 선택 → "안에서 뭐가 달라졌어?" 만 묻는다. 테이크 {n}/{N}
[금기] 접수 사연 요약해서 되돌려주기 / 좋은 선택 고르기 / 원래 선택을 틀렸다고 하기
```

### 4.9 저장과 재방문

```ts
type SessionSave = {
  topic: Topic; title: string;
  choicePoint: ChoicePoint;
  takes: Take[];
  autoLine: string;   // 1부 끝 문장
  newLine: string;    // 2부 끝 문장
  threads: string[];
};
```

- 다음 접수 화면: `newLine`이 있으면 **"🔁 저번 선택, 한 번 더"** 칩 → 1부 생략, 같은 `choicePoint`로 2부 재입장 (테이크 5부터)
- 커튼콜 인사이트 1줄은 반드시 `autoLine` ↔ 테이크 결과를 나란히
- 접수만 하고 나간 세션은 하루 3회에서 제외
